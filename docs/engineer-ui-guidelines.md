# 工程师端界面规范

工程师端以现场履约为主，采用绿色品牌色，与蓝色客户端分别维护。

## 白底视觉版本

所有工程师端业务页面及登录注册页面采用白色底面，统一使用
`engineer-refined.css`，替代 `engineer-workflow.css`，由 `data-refined`
区分新版页面；旧版公共卡片规则不再覆盖这些页面。
新版内容边距 24px，小屏 18px；主要正文 14–15px，重点标题 19–27px。
个人中心和详情以留白、浅分割线组织内容，重点任务保留轻边界，深绿用于主要操作。
搜索、筛选、列表、表单、移动仓、培训、收益、签名、AI 助手与资料图集组件
均在同一份样式中维护。普通列表以分割线分组，输入与签名区域保留边界。

## 信息顺序

- 工作台：服务身份、待办统计、下一项任务、常用工具、其他待办、辅助场景图。
- 工单列表：状态筛选、搜索与来源筛选、结果数量、统一任务卡片。
- 工单详情：当前状态、服务进度、当前操作、联系人、设备与故障、报价、现场照片、履约记录。
- 平台与企业任务汇总展示；来源、履约企业和详情链接始终保留。列表汇总不改变后端授权。

## 组件

- 页面边距 16px，小屏 12px；卡片间距 12px，圆角 12px。
- 页面标题 24px，卡片标题 16px，正文 13–14px，辅助信息 11–12px。
- 绿色用于主要操作和选中状态；所有状态必须同时提供文字。
- 主按钮最小高度 44px，一个任务阶段突出一个主要操作。
- 卡片顺序为来源与状态、设备、SN 与故障、地区与企业、单号与下一步。
- 设备缩略图为辅助识别信息；示意图片必须标明示意，不得作为维修完成证据。
- 页面的装饰图片不得挤占关键任务和操作的首屏空间。

## 实现入口

`apps/engineer-app-web/engineer-workflow.css` 维护工程师端布局与组件规范；
`market-ui.js` 维护工作台、汇总列表和平台工单详情；企业工单详情仍调用原业务流程。
客户界面不随工程师端样式调整。

## 关联页面

- 接单大厅：接单资格和履约企业在上方，关键词与设备类别筛选在任务列表前；筛选仅作用于后端已授权返回的需求。
- 培训：个人资质、课程搜索与报名状态、课程列表；报名状态和名额仍由后端校验。
- 移动仓：工作企业、库存概览、领用退操作、记录分组、搜索和结果数量；刷新保留当前搜索条件。
- 个人中心：工作身份、个人资料、常用资源、接单状态、收益与历史、服务资料；头像和技能图片管理默认折叠，减少首屏干扰。
- 同一功能避免重复入口；正常状态不常驻重试按钮，失败后显示恢复操作。

## 验收

检查 320、430、1280px 宽度的导航、文字换行、筛选、按钮与弹窗。
使用测试企业数据核对工作台数量与对应筛选结果、企业任务详情和平台履约操作。
减少动态效果偏好下不播放非必要动效；异步失败不能显示为零任务。

## 交互连续性

- 页面进入 180ms，底部栏目切换只淡入；返回时轻微反向位移。导航不等待动画结束。
- 原生弹窗进入 180ms、关闭 120ms；关闭期间禁止重复操作，保留原有 Escape 和焦点恢复行为。
- 按钮提供轻微按压反馈，异步处理设置 disabled 和 aria-busy，避免重复提交。
- 会话内按工程师账号及页面保存列表筛选条件、移动仓标签和返回滚动位置，4 小时过期；不保存业务表单、密码或上传内容。
- 带 state 参数的任务统计入口优先使用该参数，不被历史状态覆盖。
- 返回列表恢复位置；切换底部栏目正常进入页面，重复点击当前栏目回到顶部。
- 系统设置减少动态效果时，取消位移、缩放与过渡，功能及反馈文字保留。

交互实现位于 `engineer-interaction.js` 和 `engineer-interaction.css`。
