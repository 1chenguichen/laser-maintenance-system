# 平台管理后台

本地入口：`http://localhost:3103/`。平台账号与企业管理员账号、登录凭证完全分开。平台管理企业开通与服务配置；3100/3101/3102 继续处理每家企业的日常业务。

## 初次登录

初始化脚本会生成随机平台密码，凭据仅保存在本机忽略提交的 `.local-preview/platform-credentials.json`，同时在 `backend/.env` 中设置首次引导所需的 `PLATFORM_ADMIN_USERNAME` 和 `PLATFORM_ADMIN_PASSWORD`。现有用户重启时不会被覆盖。

在平台右上角可修改密码，修改后所有旧平台凭证立即失效，企业账号不受影响。凭据文件仅记录初始化密码，网页修改密码后应使用新密码；服务重启不会把密码改回文件中的旧值。平台密码通过带随机盐的 scrypt 摘要保存，接口和操作日志均不返回密码或摘要。

## 企业开通

1. 点击“新建企业”，填写企业名称、联系人、企业管理员手机号、套餐和到期日；管理账号及初始密码可填写或自动生成。
2. 当前演示环境可勾选“启用演示验证码 000000”。关闭后，该企业的客户及工程师服务需使用真实认证；企业管理账号密码不受演示验证码开关影响。
3. 提交后持久化记录企业并展示“开通中”，后台创建独立数据库、业务表和企业管理员。
4. 成功后显示“正常”，开通信息提供统一登录入口以及本次生成的企业管理账号密码。
5. 企业管理员进入3100添加工程师、客户设备和配件；客户在3101统一登录并绑定设备后报修，工程师在3102按已开通身份作业。平台看到的是这家企业的真实用量，不显示客户姓名、维修内容等明细。

业务数据库开通失败时保留失败状态和可读错误，修复权限等原因后可点击“重试开通”。重试沿用已分配数据库及企业编号，不创建第二家企业或重复管理员。当前单后端实例重启会把未完成开通标为失败，供人工重试；尚未采用分布式任务队列。

## 数据联动

| 平台操作 / 业务变化 | 实际效果 |
|---|---|
| 新建企业 | 后台按独立管理账号确定企业，客户和工程师统一按个人身份登录，企业数据独立 |
| 客户确认绑定设备、企业添加工程师、客户报修 | 平台刷新显示客户、员工及工单的真实数量 |
| 客户上传附件 | 平台统计对应企业目录的实际附件字节数 |
| 平台停用企业 | 三个端原有凭证、后续登录、附件和 WebSocket 推送均受限，业务数据保留 |
| 企业到期 | 后端按当前时间即时限制已有凭证；不依赖用户重新登录或浏览器修改日期 |
| 续期 | 三个端使用新的有效期；已停用企业仍需单独恢复 |
| 修改套餐 | 合同和财务接口按新套餐权限立即校验；历史业务数据保留 |
| 修改员工额度 | 新建工程师计入额度，并发创建受同一企业锁保护；不能降到现有用量以下 |
| 修改附件额度 | 实际上传超过额度会拒绝并清理本次文件；不能降到现有附件用量以下 |

员工数当前包含全部企业管理员与工程师账号，不包含报修客户；附件额度不含 PostgreSQL 数据库本身或内嵌签名图片。平台用量按当前数据库和本机企业附件目录读取，读取失败明确显示不可用，不显示虚假的零。

## 套餐与续期

预置基础版、专业版、企业版。基础版包含维修和库存移动仓，专业版及企业版包含合同和结算发票。每家企业可调整实际员工、附件额度以及有效期。修改套餐及有效期须填写原因，并保存修改前后内容。

现有 `demo`、`trial` 的业务数据及长期有效状态保留，默认具有专业版功能。新企业默认开通14天，可在创建时修改。套餐目前没有售价或自动扣费，续费由平台人员人工登记服务有效期。套餐页展示预置方案，不提供全局批量修改既有企业额度的入口。

## 日志与权限

平台创建、开通成功、失败与重试、停用恢复、套餐续期、登录与修改密码均产生真实操作日志。企业设置修改和日志写入同一控制库事务。日志可查看操作人、原因、企业以及修改前后的设置，不包含数据库名称、密码和登录票据。

平台凭证不能调用企业业务接口，企业凭证不能调用平台管理接口。当前不提供“以某企业身份进入业务”的支持入口；平台人员不会通过这个页面直接读取企业工单明细。

## 运行与验证

项目和本次控制表、环境配置快照均位于 D 盘。控制表升级前快照在 `.local-preview/backups/platform-<时间>/`，不改写原有业务数据。

`start-preview.cmd` 现在一并启动平台 3103。已有预览须先关闭对应进程再重新启动，不能重复占用端口。新环境需要先准备 PostgreSQL/Redis、后端 `.env`，初始化会生成独立平台凭据。

`test-product.cmd` 包含平台接口测试；`test-browser.cmd` 还检查平台真实点击和三个端联动。使用独立审计控制表和企业数据库，不向现有演示业务库写入测试工单。

- `backend/reports/platform-smoke.json`：平台身份、创建、三端互通、用量、停用恢复、套餐、并发额度、存储、到期续期、失败重试、日志和密码变更。
- `backend/reports/platform-browser/results.json`：网页创建、三端真实登录与报修、平台用量、停用恢复、套餐续期、日志和手机布局。

## 当前部署边界

本地第一版为单后端实例，共享同一台 PostgreSQL 与本地附件目录。开通仍需数据库创建权限；正式部署前应分离开通任务的运维权限与普通业务访问权限，并增加任务队列、版本化数据库迁移、集中附件存储、正式备份和恢复演练。平台登录限流当前为进程内存，正式多实例部署需迁入共享限流存储。尚未接入自动收款、短信供应商或企业自助购买。

登录体验已改为按企业名称识别和切换，平台不再要求填写企业代码；旧入口兼容和身份校验见 `ORGANIZATION-LOGIN.md`。

当前账号、角色和设备归属方式见 `UNIFIED-IDENTITY.md`。企业管理初始密码只在创建操作展示，既有企业可使用“重置企业管理密码”重新发放；重置不会注销客户或工程师个人账号。
