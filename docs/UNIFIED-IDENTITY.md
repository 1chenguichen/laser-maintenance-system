# 统一账号与设备归属

当前产品采用“先登录个人账号，再绑定设备”。用户登录时不用提供企业标识或选择企业。

## 三个端

- 企业后台（3100）：平台发放唯一的登录账号和密码，一个管理账号绑定一家企业。企业名称和业务信息在登录后的后台显示。
- 客户端（3101）：手机号对应统一个人身份。首次登录没有设备时展示绑定引导；已关联的设备和工单统一显示，并标注实际服务商。
- 工程师端（3102）：验证手机号后查询企业已开通的工程师身份，展示本人任务和移动仓。普通客户不能通过自己指定角色取得工程师权限。

一个客户可以同时拥有两家服务商的设备。报修、报价确认、付款、评价、合同和发票操作根据设备/工单/合同归属路由；企业后台始终只访问本企业数据库。选择要咨询的服务商属于业务会话，不切换登录身份，客服消息和历史按服务关系分别显示。

## 首次设备绑定

企业在业务后台建档设备，每台设备在统一目录中具有不可猜测的绑定标识。

企业设备列表的“客户绑定链接”生成统一客户端入口。客户打开链接，先登录自己的个人账号，再确认绑定设备，系统自动建立该客户与设备所属服务商的关系。该链接可作为设备二维码内容随设备交付；当前网页不模拟微信硬件扫一扫。

陌生账号不能仅凭猜测序列号认领全平台未绑定设备。未绑定设备需要服务商提供的设备绑定链接。设备已经绑定其他手机号时不能被转绑。已有服务关系中的本人已关联设备可以通过序列号重新核实。

## 身份目录与业务数据

`identity.people` 存储统一个人身份，手机号在当前认证模式下唯一；`identity.links` 关联个人、服务企业、角色和企业内原记录。原有客户、工程师、设备和工单保留在各企业数据库。

个人业务凭证不包含让客户端任意指定企业的权限。统一业务入口从服务关系和业务资源解析企业，并使用该用户在对应企业的角色执行原有受保护接口。资源具有稳定的统一引用，映射到具体企业、资源类型和企业内编号；即使两企业拥有相同 UUID，也不会混淆。企业管理员凭证不能查询另一家企业，个人凭证不能访问平台或企业管理接口。

常用地址属于个人账号，报修时复制当前地址到对应服务商的工单，不修改旧工单的地址快照。企业停用或到期只限制该企业的服务，不注销个人账号，也不影响其他正常服务商。

角色由后端已开通关系确定。`POST /identity/login` 不传角色时可以返回已识别的商家或工程师工作身份；`availableRoles` 提供工作台信息。个人认证后可通过 `/identity/switch-role` 进入已授权身份，不能自行声明管理员权限。如果同一手机号关联多个独立管理账号，企业后台仍使用平台发放的唯一管理账号，不猜测企业。

## 管理账号发放

平台创建企业时可填写管理账号和初始密码，也可留空自动生成。成功登记后的开通信息只在本次操作展示初始密码，便于平台保存并发放。后台只保存带盐密码摘要。

平台“开通信息 → 重置企业管理密码”可重新发放密码，并撤销该企业旧后台凭证；客户和工程师的个人登录不受影响。

已有企业初始化时生成唯一管理账号，交付文件位于 `.local-preview/business-accounts-<当前业务库>.json`。这是初始交付记录，网页重置后应使用新密码，服务重启不会恢复旧密码。平台账号与企业管理账号相互独立。

## 当前认证与未来客户端

当前网页的统一手机号认证仍为显式启用的演示模式，`IDENTITY_DEMO_AUTH=true` 时使用演示验证码或本地模拟验证码；未配置真实短信时不宣称短信已经发送。普通生产认证需接入真实短信供应商或微信服务端授权。

未来小程序/App 可复用同一统一用户ID、角色关系及设备绑定目录。微信身份需要经过服务端授权验证后关联统一用户，不通过客户端自报 OpenID 或企业编号决定权限。本次没有发布真实微信小程序或打包原生App。

当前统一业务层在本地单后端内向原有受保护接口转发，并聚合个人有权访问的数据。正式大规模部署需为统一业务入口、身份目录、设备目录及数据库连接配置容量管理与监控，逐步改为内部应用服务调用。

## 数据与验证

升级前备份位于 `.local-preview/backups/platform-<时间>/`。旧业务数据不清空；后续控制库快照会包含 `platform` 和 `identity` 两个 schema。正式备份需包括企业业务库、统一身份及地址、账号摘要、文件和密钥。

`test-product.cmd` 包含统一身份接口回归；`test-browser.cmd` 包含真实账号登录、先登录后绑定设备、多服务商设备和工单、按设备报修、工程师任务、消息隔离及手机布局。核心报告：

- `backend/reports/unified-identity.json`
- `backend/reports/unified-browser/results.json`

既有业务兼容测试仍保留企业内会话，用于验证未改写的工单、库存和财务流程；统一身份的跨服务商完整流程由上述新测试单独覆盖。
