# 物联网首期：模拟业务版本

日期：2026-11-07。此版本可以本地演示和验证业务；尚未接入真实激光设备。

## 使用入口

| 使用者 | 入口 | 本期能力 |
| --- | --- | --- |
| 维保云运营 | http://localhost:3103/iot.html | 全国省界地图、模拟设备分布、在线/离线/告警统计、企业开通及额度 |
| 入驻企业 | http://localhost:3100/iot | 本企业监测、历史趋势、告警处理及转服务单、接入凭证、指标配置、员工手机授权 |
| 企业手机身份 | http://localhost:3101/login.html | 登录后由服务端识别企业账号或授权员工；单企业直接进入工作台，多企业只选择企业 |
| 普通客户 | http://localhost:3101/login.html | 登录进入客户首页，查看设备、报修和订单；没有物联网入口及数据访问权限 |
| 工程师 | http://localhost:3102/iot/monitor.html | 当前任务授权设备的诊断指标；任务详情内有运行数据和告警快照入口 |

仍为四个应用入口。企业手机与普通客户共用 3101，没有新增独立 App 或端口。

演示客户手机号 **13698000001**；企业设备运营员 **13698000002**；平台演示工程师 **13690000101**。现有本地演示环境使用验证码 **000000**，不代表正式短信验证。企业及平台继续使用已有账号密码。

模拟数据：默认演示企业、华东激光、绍辉各 8 台，共 24 台；18 台每约 5 秒上报，其余刻意模拟离线或未上报。温度周期变化触发告警。演示员工在华东具有告警处理权限，在另外两家仅查看；普通客户跨企业拥有设备不表示企业间可以查看对方数据。

## 数据如何互通

沿用二维码对应的稳定设备资产 ID，映射原设备档案、客户和企业。设备监测凭证是独立密钥，二维码不是上传密钥。企业不能用请求参数切换到别家租户。

告警需要人工填写服务城市、地址和故障说明，再生成**平台服务单**。保留采集快照，继续按现有自营、外包、平台调度规则处理；不自动派工程师，不自动生成合同工单。同一告警重复或并发提交只生成一张服务单。

普通客户不提供物联网监测及原始指标；工程师在当前任务授权范围内看诊断指标。员工手机访问范围由后端授权，不由网页自行决定；停用授权后，实时连接下一轮检查会断开，REST 请求立即拒绝。

## 代码边界与运行

- `backend/src/iot`：授权、设备接入、规则、查询、实时推送、转单桥接。
- 独立 PostgreSQL 数据库：默认使用当前业务库名加 `_iot`；不是把时序样本写进每家业务数据库。权威企业、人员、设备档案继续复用已有数据库。
- `apps/iot-ingest`：独立 HTTP 采集网关进程及模拟器；网关默认仅监听本机 8181。
- `packages/iot-web`：四端共用的监测组件源码；`node scripts/build-iot-web.mjs` 同步生成静态文件。
- `packages/iot-contracts`：设备消息及业务接口约定。

四端启动后，首次执行 `node scripts/seed-iot-demo.mjs` 准备演示数据；之后双击项目根目录 `iot-demo.cmd` 启动网关和模拟器，保持窗口开启，Ctrl+C 停止。该命令不会停止四端。避免同时运行多个模拟器。

设备上传格式为 `POST /telemetry`，请求头 `X-Device-Key`，内容包含 `sampleId`、`recordedAt`、`values`。凭证只在创建/轮换时返回一次，数据库仅存哈希。演示器的本地凭证位于 Git 忽略的 `.local-preview/iot-devices.json`，不可发布。

## 地图滚动和加载性能修复（2026-11-07）

本机浏览器分析发现首次渲染存在约1528ms和1763ms的主线程长任务；接口多为几十毫秒。原因集中在地图初次重复创建、重复SVG解析以及大范围滤镜绘制。

修复：使用保留原始文件的亚像素简化显示地图（全部35个地区、339个多边形环保留，25,240个顶点降到10,611个）；浏览器地图资源约583KB降到124KB。实时刷新只更新省份样式、节点和计数，不再重新拼装SVG。移除整图模糊与密集矢量点阵绘制，扫描使用独立HTML合成层，节点脉冲改为transform/opacity；离开可视区域及页面隐藏时暂停动画，销毁时取消观察。地图加载前不提前绘制空数据地图，首屏增加读取状态。

本机相同2400×1250窗口的修复后普通测量仅记录约98ms的主线程长任务；4倍CPU限速测试的连续滚动期间未记录超过50ms的长任务。这是本机抽样，不是所有设备帧率保证。保留科技风格、节点状态、悬停、键盘筛选、动效开关和减少动态效果支持。

复测方法：`node backend/test/iot-performance.mjs` 或追加 `--cpu4`；报告在 Git 忽略的 `.local-preview/iot-performance-1x.json` / `iot-performance-4x.json`。地图交互/动画连续性、离屏暂停、企业汇总/1101台分页/详情抽屉、其余三端检查通过。测试截图核对后删除。
