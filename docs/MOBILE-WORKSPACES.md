# 移动端设备服务与企业工作身份

本轮优化保留客户端蓝色、工程师端绿色，先调整服务关系与当前任务，不改成同一套界面，也未合并为微信小程序。

客户端：
- 首页新增服务待办，展示待确认报价、待付款和明确未评价的服务；没有待办或尚未关联服务商时展示相应引导。
- 首页保留设备入口，并提供绑定设备入口。客户不需要先选择企业。
- 设备页展示设备服务商Logo、企业名称和联系入口。工单关联服务企业，不将个人账号固定到单家企业。
- 工单页保留具体下一步提示，增加查看报价/结算入口及联系当前服务商。支持原有hash链接与id查询参数，修复旧首页链接不匹配详情的问题。
- 未登记保修采用中性提示；设备型号和序列号按文本转义展示。

工程师端：
- 已登录页面展示当前工作企业、Logo和工程师身份。
- 一家企业自动进入；多家企业可选择工作企业，选择保存在当前标签页并按个人身份区分。
- 工单、指定任务、抢单、移动仓、配件、统计和工程师AI请求附带当前serviceId；后端仍验证关系和业务记录归属，跨企业资源混用会拒绝。
- 任务详情顶部复用现有操作按钮逻辑，突出当前下一步，不创建另一套业务提交路径。
- 跨企业服务关系由 /identity/services 返回个人可访问的关系及企业展示资料，不暴露企业代码或数据库信息。

新增前端资源：
- customer-app-web/service-experience.js、service-experience.css
- engineer-app-web/workspace-scope.js、workspace-experience.js、workspace-experience.css

测试：node backend/test/mobile-workspaces.mjs。

使用两个独立临时企业，同一个客户和工程师分别关联两家企业；验证客户两家设备可见、首页待办及工单联系、工程师切换后的工单和移动仓范围、当前步骤入口、蓝绿视觉与浏览器脚本错误。测试结束清理临时数据库、企业和身份关系。需要8180、3101、3102及9324浏览器测试连接。
