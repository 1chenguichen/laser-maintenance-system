# 企业租户隔离

本次实现采用每企业独立 PostgreSQL 数据库。默认企业代码为 `demo`，绑定原有业务数据库，原有业务表不搬迁、不清空。`platform` schema 保存企业与账号归属，可通过 `TENANT_CONTROL_DATABASE` 指定独立的控制数据库；本地默认放在默认企业数据库中。

## 使用

企业后台使用平台发放的唯一账号密码，一个管理账号绑定一家企业。平台后台在3103管理这些账号，可查看账号及重置密码。

客户和工程师使用统一手机号账号，不填写企业标识，也不选择企业。客户先登录，再通过服务商提供的设备绑定链接建立服务关系；已有客户档案会接入统一身份目录。同一客户可以查看多家服务商的本人设备与工单，企业侧仍只访问本企业数据。详见 `UNIFIED-IDENTITY.md`。

演示验证码000000仅用于当前显式启用的个人演示认证。企业管理账号和平台管理账号分别使用独立密码。真实短信和微信授权尚待配置。

## 隔离边界

- 登录签发的 JWT 包含企业、账号归属、角色与版本。每次 HTTP 请求及 WebSocket 收发重新检查企业和账号启用状态，业务接口只从已验证身份确定企业。请求头不能切换数据库。
- AsyncLocalStorage 绑定本次请求的数据库连接。注入的 Repository、EntityManager、事务及原生 SQL 查询均解析到当前企业数据库。未解析企业的 HTTP 请求禁止访问数据库。不存在企业或连接失败时拒绝请求，不回退到默认企业。
- Redis 验证码、会话、位置及业务缓存带企业前缀。人工客服等待队列、活跃会话、工程师内存位置带企业作用域。
- WebSocket 房间带企业、角色与账号，即使两企业存在相同客户 UUID 也不会相互接收消息。移除了原先重复且未鉴权的 Gateway，客户端业务写入统一经过 HTTP 鉴权。
- 附件存放在 `backend/uploads/<tenant-id>/`，不再公开整个 uploads 目录。页面从已授权业务响应得到 15 分钟有效的签名地址；地址是短期查看授权，可被持有者在有效期内分享。账号或企业停用后地址同时失效。文件票据不能调用业务 API。过期后重新打开详情取得新地址。
- 默认企业旧工单中引用的附件由迁移命令复制到企业目录，旧文件保留；其他企业没有旧目录回退权限。签名图片等原有内嵌数据仍随所属工单保存。
- 工程师 Dify 用户标识包含企业及工程师 ID，已有 conversation_id 必须在本企业 Redis 中登记且属于本账号。实际外部 AI 服务仍需单独配置。

## 本地维护命令（项目根目录 CMD）

先编译后端，所有命令均在 D 盘项目中运行：

```cmd
node backend/node_modules/typescript/bin/tsc -p backend/tsconfig.build.json
node scripts/tenant-admin.mjs list
node scripts/tenant-admin.mjs backup
node scripts/tenant-admin.mjs create example "示例企业" 13800138000 --demo
node scripts/tenant-admin.mjs migrate-files
node scripts/tenant-admin.mjs status example disabled
node scripts/tenant-admin.mjs status example enabled
node scripts/tenant-admin.mjs status example disabled 13800138000 cs_operator
```

创建企业会建立空数据库和管理员，不复制默认企业的数据。去掉 `--demo` 会创建关闭演示认证的企业。`status` 的账号操作增加凭证版本，旧登录不能恢复使用。企业操作停用所有现有访问，重新启用后未过期的账号凭证可继续使用。

维护命令优先使用显式环境变量 `DB_DATABASE`，其次使用 `.local-preview/database.txt` 中的当前预览数据库。审计测试使用 `laser_audit_20261025` 及其独立 `platform` 注册表，与正常预览企业分离。维护命令只能由可访问本机数据库的运维人员执行，企业创建接口仅向独立平台管理员开放，不向匿名用户或企业管理员开放。

`backup` 在只读一致性事务中导出 public 业务表数据及行数到 `.local-preview/backups/tenant-<时间>/`，用于本次无损升级的核对。它是数据快照，不替代正式 PostgreSQL 备份：正式部署应配置 pg_dump、数据库与文件定期备份及恢复演练。此次升级没有删除或重写原有业务行。旧附件保留在原位置，企业目录为复制件。控制表和签名密钥也应纳入正式备份。

```cmd
test-product.cmd
test-browser.cmd
```

前者运行原有业务回归、仓储合同财务回归，以及 13 组跨企业检查。后者还连接专用 Edge 测试窗口，检查原有业务真实点击与三个角色的企业切换。结果位于 `backend/reports/`，租户报告为 `tenant-isolation.json` 和 `tenant-browser.json`。测试使用独立审计数据库；用户正常业务库不写入测试单据。

## 当前适用范围

已增加独立的平台管理界面（3103），可创建企业、人工管理套餐有效期、停用恢复并查看用量与日志，见 `PLATFORM-ADMIN.md`。尚未接入自动订阅计费和企业自助购买。运行时最多缓存 30 个企业连接池，每池最多 3 个连接（默认企业沿用主连接池），超过上限拒绝连接；大量企业上线前需连接回收或独立连接代理。数据库 schema 升级需逐企业执行版本化迁移，目前仅新企业开通时创建 schema。

数据库创建与运行仍使用同一服务器账号；正式部署需分离运维和运行权限，并为企业数据库配置最小权限。当前客服等待队列仍为进程内存，扩展到多实例前需迁到共享存储。新增异步任务须显式进入经过验证的企业上下文，不能依赖默认数据库。演示验证码、模拟支付和未配置短信均不能视为正式商用认证或收款服务。


## 同浏览器多企业登录（2026-11-06）

企业后台的登录令牌与用户资料保存在当前标签页的sessionStorage，各标签页可分别登录不同企业；刷新保留本标签页身份，退出只清理本标签页。旧版localStorage共享凭证不自动继承，升级后需重新登录一次。新开空白标签页需自行登录；浏览器复制标签页可能初始复制原标签页的身份，之后两页的登录和退出仍独立。

皮肤和企业资料变更通知仍可跨窗口共享，不承载身份信息。客服工作台、设备编辑、API请求统一读取本标签页令牌。后端企业隔离校验继续生效。

验证：node backend/test/multi-company-tabs.cjs（使用两个真实企业账号及同一浏览器上下文，仅查询和打开表单，不写入业务数据）。
