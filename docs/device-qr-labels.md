# 设备二维码与客户扫码绑定

## 企业后台

在「设备管理」中，每行可打开「设备二维码」，复制链接、下载 SVG 二维码或打印包含企业名、设备型号、SN 的标签。勾选设备后可批量打印，单次最多 50 台。

新建设备、Excel 导入以及编辑设备沿用 identity.assets 的稳定设备标识。旧设备首次打开二维码时补齐标识。重复打开不会换码；不同租户相同 SN 对应不同设备码。

二维码使用固定的设备标识，不写入客户电话、账号密码、工程师或当前外包企业。售后关系变更无需重新印码，扫码时读取企业当前配置；具体执行方仍由实际派单确认。

## 客户端

「我的设备 → 扫码绑定设备」支持相机实时扫码、拍照/相册识别，以及粘贴二维码链接。设备识别后展示设备型号、SN、所属企业、保修及售后安排，用户确认后才绑定。

未登录先登录，登录后回到原设备。已属于自己的设备可直接查看档案或报修，报修自动携带该设备 ID。其他客户已绑定的设备禁止抢绑；如需转移，由所属企业管理员核实后调整设备客户。

设备码只用于识别档案；扫描本身不创建工单、不派单，也不更改设备所属企业。

## 地址与打印

本地预览默认推荐局域网客户端地址（4101），手机需与电脑同网、预览服务持续运行；相机实时扫码要求浏览器支持并允许权限，且运行于 HTTPS 或 localhost。普通 HTTP 手机演示使用「拍照 / 从相册识别」。图片在浏览器本地解码，不上传到服务器。

正式贴标前，在二维码窗口的「客户端访问地址」填写固定域名；后端也可配置 CUSTOMER_WEB_URL（例如 https://service.example.com）。界面按企业保存地址偏好。局域网 IP 变化会使旧演示链接失效，正式域名应保持稳定。

二维码固定为黑白并包含留白；打印标签约 76 × 80 mm，浏览器可选择打印或保存为 PDF。SVG 可缩放用于标签排版。生产前应使用实际打印机和标签材质做扫码试印。

## 验证

- 后端及企业后台 TypeScript 检查。
- `node backend/test/device-labels.mjs`：真实浏览器验证二维码解码、局域网链接可达、SVG 下载、打印窗口、勾选打印入口、拍照识别、登录续接、绑定及重复扫码、不同企业同 SN 隔离、跨企业管理权限与抢绑保护、三种售后安排、报修设备 ID 和手机布局。
- 测试使用临时设备与客户，结束时清理；不修改现有售后策略。

浏览器测试验证了打印窗口与标签内容；未连接实物打印机，也未代替真机摄像头和微信内置浏览器验收。
