# 六类图片资料

- 设备：从客户端“我的设备 → 设备详情与照片”进入。全貌为主图，铭牌和部件为缩略图，支持上传、放大及移除。已绑定客户和所属企业管理员可维护，相关工程师按任务关系查看。
- 工单：平台工单、企业工单详情新增“报修时 / 检测中 / 完工后”照片。原平台报修附件归入报修时；客户仅可补充报修照片，获派工程师在相应工作阶段上传检测或完工图。完成/取消后不允许修改。现有企业工单中的原故障照片继续保留展示。
- 培训：课程封面，以及可展开的培训地点和实训图片。平台运营页“维护课程与地点图片”可上传，客户端和工程师端读取同一资料。
- 工程师：个人资料及服务身份页可维护本人头像和技能图片；获审核的工程师有公开资料页，展示实际姓名、服务介绍和所属企业 Logo。客户从平台工单中的工程师姓名进入。
- 配件：移动仓显示配件缩略图，展开后查看实物、包装和型号标签。企业后台配件列表中维护这些图片，工程师只读。
- 企业：从设备服务商或服务卡片进入企业介绍。显示已有企业 Logo、服务信息、团队和维修环境图；企业后台“企业资料”维护图片。

示意图明确标注 AI，实际上传后优先显示实拍图。未上传的铭牌、头像和服务现场记录保留占位和上传入口，不生成虚假身份或维修证据。新增的课程实训、培训地点、保护镜片、铜喷嘴、备件套装由内置 image_gen 生成，提示词记录于 `assets/service-visuals/manifest.json`。五张新增 WebP 合计约 197 KiB。

图片存放在 D 盘后端的 `private-market-media`，元数据保存在控制库 `market.visuals`。读取经过身份及企业/工单关系校验，企业介绍、已公开课程和已审核工程师资料供登录用户展示；设备、配件和工单按业务授权访问。每张输入最多 5 MiB，接受 JPG/PNG/WebP，后端解码并转换 WebP；单项资料最多 12 张，每个账号每日上传上限 60 张。正式运营仍需补充备份、附件生命周期及相应容量运营策略。

验证：设置 `VISUAL_GALLERY_AUDIT=1` 后运行 `node backend/test/mobile-workspaces.mjs`，覆盖六类图片 API、企业隔离、阶段限制、跨端读取，以及浏览器上传、刷新、放大、移除和三种屏幕宽度。测试使用临时企业与账号，完成后清理测试数据和文件。
